# AI 编排

独立的 TypeScript 模块，入口为独立的「AI 编排 Beta」菜单；「测试编排」继续保留。AI 读取真实手机界面，自主选择交互、识别、画面检查和计时操作，生成现有编辑器的线性流程。

所选 App 的包名限定执行范围。规划、点击/输入和截图采样都会核验前台应用；离开目标 App 时停止并保留已有流程，不会通过桌面图标猜测或替换应用。允许处理 Android 系统权限弹窗。流程局部修改也不能将启动节点改成其他包名。

## 两种方式

AI 编排使用 Qualix AI 任务首页，在对话输入卡片中选择「流程编排」或「自主任务」后发送；工作区使用统一对话区，模式按新建选择自动切换；历史对话合并展示，点击后恢复对应类型。流程任务自动显示画布，自主任务自动显示操作记录、计划进度与执行结果，两种模式均可通过历史对话旁的设备预览按钮打开可拖动的悬浮窗口，队列和笔记使用工作区内的直接入口；录像仅在自主任务中提供。本目录只负责 Appium 画布方式；自主任务位于 `ai-task/`，直接依据截图和坐标执行，不读取组件树，不产生流程节点，也不保存到 Appium 脚本列表。两种方式的任务、历史、计划、笔记与录像索引分别保存，切换不清空任一侧的数据；设备和模型设置共用，操作设备时共用互斥锁。

## 工作区

- 原实验室位置替换为独立的 AI 编排 Beta 菜单。左侧设备预览、中间共用流程画布、右侧对话，三个区域可拖动调整。
- 系统设置与运行准备：配置共用模型、Android SDK 与报告路径，检查连接设备、App 和图片模型。
- Flash 适合快速完成一个目标；Pro 维护多个测试目标和检查证据，支持跨页面继续测试。
- 启动自动化任务编排可将任务加入后端队列，同一设备依次执行；切换页面不影响任务，可从队列打开、终止、重新排队或删除。重启服务不会自动重发未完成操作。
- 笔记与计划展示实际测试进度与页面访问；用户笔记单独保存，新的执行要求应通过对话发送。
- 流程编排不录屏，也不显示录像选项或播放入口；自主任务保留录像和播放功能。
- 完成的流程由后端保存为现有 Appium 脚本，可直接运行，也显示在手动编排列表；失败草稿保留供编辑保存。

## 使用

1. 使用现有 Android SDK / ADB 连接并解锁手机，在「参数配置 → 测试编排配置」中测试并保存 AI 识别模型。
2. 打开「AI 编排」。左侧复用设备预览组件，中间为实时流程画布，右侧为对话区。可拖动两条分隔线调整宽度，布局比例会保存在当前浏览器。
3. 在新建区域选择 App、任务类型和设备后发送测试目标。脚本名称根据 App、首轮目标和时间自动生成；发送前验证模型连接，发送截图时验证图片输入能力；默认发送设备截图，可在新建输入区右上角关闭。关闭后只发送节点信息，AI 画面识别不可用。
4. 执行步骤实时写入中间画布。成功后自动保存到现有脚本库，可点击「运行脚本」直接回放，也会显示在「手动编排 → 脚本列表」中。
5. 实时流程直接复用手动编排的完整编辑器，包含搜索、放大、复制、删除、节点编辑、插入与执行。修改后需保存再运行。「手动编辑」也可打开同一份已保存脚本，使用独立的手动编排页面。若手动页面有未保存的内容，先提示再加载。
6. 后续对话默认按描述局部修改对应节点，保留其他节点、ID 和顺序，并更新同一脚本；只有明确要求重新生成完整流程时才重建。需要继续探索设备时，从当前界面追加操作。运行中可发送补充要求，下一轮决策会采用新消息并丢弃过时决定；消息保存到当前历史对话。Enter 发送，Shift + Enter 换行，中文输入法确认候选词不会触发发送，发送失败会保留输入。「新对话」创建独立脚本，未保存流程先归档，不影响已有脚本。
7. 停止或失败时保留已执行步骤，点击「保存脚本」后再编辑或运行。模型验证失败且没有新步骤时保留原画布和已保存脚本。保存失败可重试，未保存的新流程不能直接运行。
8. 生成和运行期间禁止开启新对话，需先终止并等待任务结束。生成、保存和回放期间锁定本页与手动编排的设备操作；切换菜单保留对话和当前任务。实时流程的「执行日志」仅展示脚本回放内容，运行结果同时在对话中显示用时；AI 编排进度在对话区展示，模型调用详情随历史保存。清除执行日志不删除 AI 编排历史。

支持：启动 App、元素点击、覆盖输入（含中文）、清空、长按、四向滑动、返回/主页/回车、短暂等待、等待元素和文本断言，以及 AI 单帧/持续识别、成对画面变化、计时打点和日志。只生成线性流程。工具由 AI 按目标与真实结果选择，没有针对某个 App 或目标关键词的固定路由。中止、失败或达到上限时保留已执行步骤，可打开编辑器修正。

## 跨页面任务与决策

- 使用任务清单、当前子任务、历史结果和检查证据驱动决策，全部在本目录中使用 TypeScript 实现。两种模式复用已有模型配置；Pro 使用计划与实际执行证据校验，不引入独立的多代理运行时。
- 模型首轮在动作中提供 `plan` 测试项（最多 20 项），之后用 `taskId`、`pageName` 和 `taskNote` 说明当前任务、实际页面和简短事实进度。计划描述测试结果目标，点击和返回等导航动作不单独当成完成项。允许补充新项，不允许删除、改名或弱化已有目标。
- 每轮按“观察当前页面 → 核对上一动作结果 → 更新任务进度 → 选择操作”决策。程序持续提供所有待完成/进行中/已完成项、检查节点、页面访问记录和重复路线信息；即使最近历史被截断，任务账本也完整保留在当前生成任务内。
- `assertText` / `assertExists` 成功、AI 识别返回或画面比较结束后，程序才为当前项记录实际检查证据。模型下一轮阅读结果，用 `completedTaskIds` 确认已满足目标的项；无证据的声明会被拒绝并重新规划。识别/画面比较有返回并不自动代表业务目标通过，是否满足目标仍由模型结合实际结果判断。
- 同一 Activity 下结合可见节点识别不同页面，忽略数字时钟/计数变化、输入框内容和位置变化。页面签名仅作辅助，模型仍需参考最新节点和截图。正常返回旧页面完成新测试项不会被禁止；同一路线在没有新增完成项时重复两次起提示调整，重复四次停止并保留已有节点。任务信息或提前完成连续三次不符合检查规则也会停止。
- 只有所有测试项均有完成证据才允许结束；最后一项可由 `finish` 的当前真实节点检查完成。任务账本写入每轮模型输入，清单与完成记录写入现有历史日志。生成后回放仍执行普通线性脚本；运行时不重新调用规划模型，已有 AI 识别节点仍按原有方式执行。

## 历史对话

- 右侧对话区顶部「历史对话」可查看、恢复、重命名或删除历史记录。每条记录右侧的编辑按钮可设置任务名称，后续自动保存会保留名称，不改变关联脚本名称。新对话和切换历史前会先保存当前对话；刷新页面后也可通过该入口恢复。
- 独立数据库位于数据目录下的 `.midscene-app/ai-conversations.sqlite`，记录对话消息、App、流程草稿、关联脚本、最近执行日志和状态，独立于原脚本库。
- 每条需求下的「模型调用记录」可展开查看本次编排各轮规划/AI 识别的模型返回思考内容。支持接口返回的 `reasoning_content`、`reasoning`、文本形式 `reasoning_details` 和正文 `<think>` 内容；不要求模型额外生成思考内容，不保存加密字段。模型未返回时明确显示空状态，旧历史也不会补造。API Key 会从记录的文本中脱敏；响应格式错误仍保留该轮返回供排查。
- 聊天中的记录入口显示为「用时 xx >」，统计该条需求各轮模型响应耗时之和；展开后仅展示各轮模型返回的思考内容，不展示提示词、截图和原始返回正文。该数值不代表设备事件耗时，也不包含所有截图、采样和操作时间。
- 每轮实际发送的提示词与截图继续保存到同一历史库的 `model_inputs` / `model_images` 表，截图在同一对话内按内容去重，对话快照只保存请求引用；聊天详情不展示这些输入。请求失败或终止时也保留已发送输入，不保存鉴权请求头。
- 删除历史对话会要求确认，并清理该对话的模型请求、截图和关联测试脚本，测试编排列表同步刷新；其他对话仍引用的脚本保留。生成中的当前对话不可删除；已有未保存流程也会先归档，避免新对话直接丢失内容。
- 本功能加入前未持久化的旧对话无法补回。设备实时预览和未提交给模型的采样帧不另外归档；日志保留最近 20 万字符，对话消息保留最近 200 条。
- 页面步数设置已移除，服务端仍保留有界动作和总时限，防止异常无限执行。

## 观察与测量

- 理解当前画面使用 AI 识别；分析过程或首次出现时间使用持续采样；比较两个时点的指定区域使用成对画面变化。区域变化只说明像素发生变化，不等于指定业务事件发生。
- 对触发后立即观察的目标，模型可生成 2～8 步的连续操作段（最多一次设备交互），执行前校验全部引用，段内不插入模型规划、组件树读取或额外等待。输出仍是现有编辑器可编辑、保存和回放的普通线性节点。
- 持续观察可关联前面的开始计时节点。生成与回放均使用该计时起点标注截图时间；模型根据截图采样时间回答，不能使用推理耗时或结束计时值推测事件耗时。计时结束日志表示整个操作段经过时间，包含模型分析；不作为首个事件发生时长。
- 首帧已命中只能给出时间上界；后续帧首次命中只能给出采样区间，精度受截图速度、采样间隔和自动化操作开销影响。已发生的事件不能倒推，需恢复起始状态后重新触发。
- AI 识别配置中可编辑「观察时间原点」。关联计时器需通过完整流程启动，单独测试该节点无法还原触发时刻。
- 同一目标的反复点击不再因时钟等无关文字变化而重置计数；达到重复限制会停止并保留已有节点。
